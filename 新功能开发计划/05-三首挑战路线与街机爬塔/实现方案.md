# 三首挑战路线与街机爬塔实现方案

## 1. 功能目标

把现有“3 把正式局 + 1 把赠送局”扩展成可选择路线、承担风险、获取收藏奖励的独立玩法。普通 3+1 流程继续保留，挑战路线使用独立状态服务，避免破坏 `MatchFlow`。

首发一轮控制在 3 首 Boss 主线 + 可选奖励局，约 15～30 分钟。

## 2. 首发路线

- **稳定路线**：星级缓慢上升，可选择恢复，奖励标准。
- **冒险路线**：更高星级和随机歌曲，奖励倍率较高。
- **极限路线**：跨关保留血量、限制 Miss，失败后结束本轮。

每首结算后出现 2～3 个分支，例如：

- 恢复 20% 路线血量。
- 下一首路线积分 +20%，但卷轴速度 +10%。
- 下一首 Miss 不得超过 5。
- 随机歌曲，完成后奖励翻倍。
- 获得一次 Combo 护盾。

Combo 护盾只能保护路线目标，不能伪造正式全连记录。

## 3. 关卡结构

1. **Stage 1 热身**：从玩家适合的星级范围选歌。
2. **Stage 2 强化**：玩家选择增益或风险。
3. **Stage 3 Boss**：固定或动态 Boss 曲池，带明确规则预告。
4. **Bonus Stage**：满足三关评级、未复活等隐藏条件后开放。

## 4. 数据驱动路线

路线不能硬编码在场景脚本中。建议定义：

```gdscript
{
  "route_id": "stable_v1",
  "seed": 12345,
  "nodes": [
    {
      "node_id": "s1",
      "stage": 1,
      "type": "song",
      "song_query": {"star_min": 6, "star_max": 9},
      "modifiers": [],
      "next": ["s2_heal", "s2_risk"]
    }
  ]
}
```

节点类型：`song`、`choice`、`rest`、`boss`、`reward`。

## 5. TowerRun 状态

建议保存到 `user://feature_data/tower_runs_v1.json`：

```gdscript
{
  "run_id": "UUID",
  "route_id": "stable_v1",
  "seed": 12345,
  "status": "active",
  "current_node": "s2_risk",
  "completed_nodes": [],
  "route_hp": 82,
  "revives_used": 0,
  "active_modifiers": [],
  "reward_multiplier": 1.2,
  "selected_chart_hashes": []
}
```

进入歌曲前和结算后各保存一次。异常恢复时回到当前节点开始前，不从歌曲中间恢复。

## 6. 选歌策略

路线节点只描述条件，由 `SongLibrary` 返回候选：

- 模式、子模式、星级、BPM。
- 是否未玩过。
- 是否排除本轮已选歌曲。
- 是否属于 Boss 曲池。

候选不足时按固定层级放宽条件，并记录原因：先放宽星级，再允许已玩歌曲，最后进入安全曲池。绝不能生成空节点或死循环。

同一 seed 必须生成相同路线和候选顺序。

## 7. 规则修饰器

复用派对模式的 `RuleModifier` / `RuleRuntime`。首批修饰器：

- `scroll_speed_multiplier`：只改变卷轴速度。
- `max_miss_limit`：超过上限结束当前关。
- `shared_hp_between_stages`：跨关保留路线血量。
- `route_score_multiplier`：只影响路线积分。
- `hidden_mode_override`：临时轨迹隐藏。
- `one_time_combo_shield`：保护路线目标一次。
- `perfect_streak_bonus`：连续 Perfect 增加路线积分。

每个修饰器声明：ID、版本、冲突组、应用顺序、是否允许正式成绩。

## 8. 正式成绩边界

- 路线歌曲可增加游玩次数。
- 影响判定、得分、血量或断连的修饰器默认不更新正式最高分和鬼影。
- 纯视觉修饰器由 `RunEligibility` 决定是否认可。
- 路线积分独立保存，不能混进普通歌曲分数。
- 路线奖励只提供称号、头像框、玩家卡片和演出装饰。

## 9. UI 与流程

### 路线地图

- 街机风格 2D 节点图，不做重型 3D 地图。
- 已完成节点显示评级，当前节点高亮。
- 分支明确显示风险、奖励倍率和修饰器。
- 键盘、鼠标、踏板均可操作。

### Boss 演出

- Boss 名称条。
- 开局前规则预告。
- 专属结算徽章。
- 不在密集判定阶段使用遮挡音符的全屏特效。

## 10. 技术结构

新增建议：

- `core/tower/route_catalog.gd`
- `core/tower/route_generator.gd`
- `autoload/tower_run_service.gd`
- `scenes/tower_map/`
- `scenes/tower_result/`
- `ui/modifier_badge.gd`
- `tests/test_tower_route_generation.gd`
- `tests/test_tower_run_recovery.gd`
- `tests/test_rule_modifiers.gd`

主要接入：

- `song_select.gd` 支持路线查询约束。
- `gameplay.gd` 应用 RuleRuntime。
- `settlement.gd` 返回路线地图，而不是进入普通续币分支。
- `profile_store.gd` 只接收最终奖励，不保存整轮状态。

## 11. 不做事项

- 首版不做无限随机肉鸽。
- 不替换普通 3+1 把流程。
- 不允许修饰器伪造正式最高分、全连或鬼影。
- 不支持歌曲中途存档恢复。
- 首版只做少量经过测试的修饰器。

## 12. 验收标准

- 三条路线均可生成非空三关。
- 相同 seed 的路线完全一致。
- 候选不足时安全放宽，不产生死循环。
- 节点完成和奖励以 run_id 幂等处理。
- Boss 失败、主动退出和异常恢复都有明确结果。
- 非标准修饰器成绩不污染正式记录。
- 普通 3+1 把流程与当前版本一致。

## 13. 风险与回滚

| 风险 | 处理 |
|---|---|
| 无候选歌曲 | 分级放宽并使用安全曲池 |
| 修饰器冲突 | 冲突组、固定顺序、组合测试 |
| 重复奖励 | run_id 与节点完成 token 幂等 |
| 破坏普通 MatchFlow | TowerRunService 独立实现 |
| 奖励倍率失控 | 倍率硬上限，奖励以收藏品为主 |

回滚时隐藏挑战路线入口，未完成 Run 标记暂停；普通模式不读取其状态。
