# 个人最佳鬼影实现方案

## 1. 功能定位

个人最佳鬼影用于把“历史最高分”从一个静态数字变成实时竞争对象。玩家重打同一谱面时，可以看到当前表现相对历史最佳是领先还是落后，并在结算时知道具体在哪个时间段完成超越或丢失优势。

MVP 不渲染虚拟人物，只提供音游最有价值的信息：

- 实时分差。
- 当前与历史 Combo 对比。
- 历史最佳的判定轨迹。
- 领先/落后时间轴。
- 最终超越节点。

## 2. 玩家流程

### 选歌详情

当谱面存在兼容鬼影时显示：

```text
个人最佳：9,850,000
鬼影：可挑战
```

玩家可选择：

- 关闭。
- 自动挑战个人最佳。
- 选择最近一次成绩。
- 选择本机其他玩家导入的挑战记录。

默认只自动加载个人最佳，不扫描所有鬼影文件。

### 游戏 HUD

建议在不遮挡主轨道的位置显示：

- `领先 +12,500` / `落后 -8,200`。
- 当前 Combo 与鬼影 Combo。
- 一条低高度进度带，青色领先、洋红落后。
- 关键超越时短促提示，不全屏闪烁。

### 结算

显示：

- 是否击败鬼影。
- 最大领先和最大落后。
- 首次稳定领先时间点。
- 失去领先的主要片段。
- 是否保存为新的最佳鬼影。

## 3. 鬼影记录格式

### 3.1 身份与兼容

每个记录必须绑定：

- chart_hash。
- parser_version。
- judge_version。
- ruleset_id。
- 玩家数与对应玩家。
- 判定窗口版本。
- 游戏速度必须为 100%。
- 自动播放必须为 false。

路径：

```text
user://ghosts/<chart_hash>/<record_id>.ghost
```

索引：

```text
user://feature_data/ghost_index_v1.json
```

### 3.2 紧凑事件

不要保存完整 Dictionary 数组。建议二进制头 + 紧凑事件：

```text
Header
- magic: E5GH
- schema_version
- chart_hash
- judge_version
- ruleset_id
- score
- accuracy
- max_combo
- event_count
- checksum

Event
- note_index: uint32
- diff_ms: int16（限制在合理判定范围）
- judge_code: uint8
- combo_after: uint16/uint32
- score_after: uint32/uint64
```

可以先使用 `FileAccess.store_var(..., true)` 压缩实现 MVP，但必须保留 magic、版本和 checksum，后续再迁移成严格二进制格式。

## 4. 录制策略

- 对局中只在内存追加事件。
- 结算时通过 RunEligibility 判断是否可保存。
- 只有以下情况写新文件：
  - 首次有效成绩。
  - 最高分提高。
  - 同分但准确率更高。
  - 同分同准确率但 Miss 更少。
- 写入临时文件，校验后原子替换。
- 保留个人最佳和最近 N 条，默认 N=3。

## 5. 实时比较算法

每个当前判定事件通过 note_index 找到鬼影对应事件：

- 比较 `score_after` 得实时分差。
- 比较 `combo_after` 得 Combo 差。
- 找不到对应 note_index 时标记记录不兼容并停止比较，不影响当前游戏。
- Hold tick 数量和 parser 版本变化可能导致事件序列不同，因此必须以 note_index 映射，不能只按数组下标。

鬼影时间轴可以预先生成稀疏采样点，例如每 500ms 一个累计分数，减少游戏中查找成本。

## 6. 挑战记录导入导出

增强版支持导出单文件 `.e5challenge`：

```text
manifest.json
record.ghost
optional-avatar.webp
```

安全要求：

- 不包含原歌曲和谱面版权内容。
- manifest 限制字段长度。
- 校验文件大小、magic、checksum 和 chart_hash。
- 导入名称不得控制目标路径。
- 不信任导入的显示分数，必须从事件重新计算或验证。

导入后如果本地没有对应谱面，只进入“待匹配挑战”，不能误绑路径相似歌曲。

## 7. 技术架构

### 新增建议

- `core/ghost_record.gd`：格式、校验和编码。
- `autoload/ghost_store.gd`：索引、加载、保留策略。
- `core/ghost_comparator.gd`：实时比较。
- `ui/ghost_hud.gd`：分差和进度带。
- `scenes/ghost_manager/`：记录管理和导入导出。
- `tests/test_ghost_record.gd`。
- `tests/test_ghost_comparator.gd`。
- `tests/test_ghost_corruption_recovery.gd`。

### 修改点

- `gameplay.gd`：启动录制、加载比较器、发送判定。
- `song_detail.gd`：鬼影选择入口。
- `settlement.gd`：结果摘要和保存提示。
- `profile_store.gd`：不直接塞鬼影数据，只保留可选入口兼容。

## 8. 2P 处理

MVP 建议：

- 1P 正式支持个人鬼影。
- 2P 每位玩家独立鬼影，需要有独立档案身份后再开放。
- 当前只有单一 ProfileStore 时，2P 不写入“个人最佳鬼影”，避免把两人结果混进一个档案。
- 派对模式和非标准规则不生成正式鬼影。

## 9. 非目标

- 不做联网实时同步。
- 不渲染 3D 或人物舞蹈鬼影。
- 不保存输入键盘扫描码，只保存判定结果。
- 不允许训练、自动播放或规则修改局覆盖正式最佳。
- 不因鬼影损坏阻止玩家开始歌曲。

## 10. 验收标准

- 同谱面重命名路径后仍能匹配鬼影。
- 谱面内容变化后明确显示不兼容。
- 实时分差与离线重算结果一致。
- 鬼影损坏时自动隔离，游戏正常继续。
- 新纪录写入中断后旧最佳仍完整。
- 自动播放、训练和非标准规则不写正式鬼影。
- HUD 可关闭，关闭后不影响录制资格。
- 10000 个事件的鬼影加载和比较不产生明显卡顿。

## 11. 风险与回滚

| 风险 | 影响 | 应对 |
|---|---|---|
| 谱面更新后事件错位 | 分差错误 | chart_hash + 版本 + note_index 映射 |
| 文件不断增长 | 用户目录膨胀 | 每谱面保留最佳和最近 N 条 |
| 游戏中频繁序列化 | 掉帧 | 内存录制，结算一次写入 |
| 导入文件恶意构造 | 崩溃或路径攻击 | 大小限制、格式校验、固定目标目录 |
| 分差 HUD 干扰主视线 | 降低可玩性 | 默认窄条、可关闭、性能模式简化 |

回滚时关闭鬼影 HUD 和入口；GhostStore 保留文件，不影响现有最高分记录。
