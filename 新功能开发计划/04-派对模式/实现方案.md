# 派对模式实现方案

## 1. 功能定位

派对模式利用当前已经存在但锁定的“派对”大模式入口，提供真正不同于普通 2P 竞分的本地娱乐玩法。设计重点不是更严肃，而是让两个人在同一台机器前产生互动、救场、甩锅和反转。

首发建议只做三个规则，避免一次铺太大：

1. 接力模式。
2. 合作血条。
3. Combo 炸弹。

随机反向、轨道交换等高干扰事件放到后续扩展，并且必须提前预告。

## 2. 入口与流程

### 大模式

把现有 `mode_select.gd` 中派对模式从锁定状态改为可进入，但仅在以下条件满足时开放：

- 2P 输入配置完整。
- 当前至少有一个兼容派对模式的子模式和歌曲。
- Feature Flag 开启。

### 子模式

派对模式不直接复用花式/竞速子模式文案，建议首批：

- 接力。
- 合作。
- 炸弹。

选歌仍复用 SongLibrary，但需要过滤不适合当前规则的谱面，例如只有单人轨道定义且无法安全映射的谱面。

### 结算

结算要显示团队或对抗结果，而不是硬套普通 1P 面板：

- 接力：团队总分、每人负责区间、交接失误。
- 合作：共享血量最低点、双方救援贡献。
- 炸弹：炸弹传递次数、引爆次数、最终胜者。

## 3. 统一规则修饰器

派对、爬塔、挑战设置类任务都会修改规则。建议先建立 `RuleModifier` 接口：

```gdscript
class_name RuleModifier

func id() -> String
func on_run_start(context: Dictionary) -> void
func on_judgement(player: int, report: JudgeReport, state: Dictionary) -> void
func on_combo_changed(player: int, combo: int, state: Dictionary) -> void
func on_tick(delta: float, state: Dictionary) -> void
func result_summary() -> Dictionary
func is_official_score_eligible() -> bool
```

Gameplay 只维护一个 RuleRuntime，不在主脚本里为每个派对规则堆大量 if/else。

## 4. 首批规则设计

### 4.1 接力模式

#### 规则

- 以时间或小节切分控制权，默认每 15 秒交接。
- 当前控制玩家的输入计分，非当前玩家输入忽略或只做视觉反馈。
- 交接前 3 秒显示明确倒计时和目标玩家。
- 交接时提供 1～2 拍保护窗口，避免临界音符归属模糊。
- 可选“失误惩罚”：当前玩家连续 Miss 后提前交棒。

#### 谱面处理

MVP 两位玩家打同一套可映射轨道。不要在首版动态重排音符。情侣谱面需要单独定义是否支持。

### 4.2 合作血条

#### 规则

- 双方共享一条团队血量。
- 每位玩家保留个人分数和 Combo。
- Perfect 可小幅恢复团队血量，Miss 明显扣除。
- 一方处于危险状态时，另一方连续 Perfect 触发“救援连击”。
- 团队血量归零失败，但结算仍显示双方贡献。

#### 防滥用

不能让高手通过空按替代另一方，也不能让一方完全不参与仍获得同等奖励。至少需要：

- 参与音符数门槛。
- 个人失败贡献统计。
- 奖励按团队通关和参与度共同判断。

### 4.3 Combo 炸弹

#### 规则

- 初始炸弹随机在一方，但使用稳定种子。
- 持有者达到指定 Combo 或连续 Perfect 后把炸弹传给对方。
- 炸弹有倒计时；持有者 Miss 或倒计时归零时引爆。
- 引爆扣除派对生命或记一分给对手。
- 全曲结束按引爆次数和剩余生命决胜。

#### 公平性

- 传递阈值按谱面密度自适应，不能固定 50 Combo 造成低密度歌曲无法传递。
- 连续长 Hold 不应让炸弹机制停摆。
- 关键状态用颜色、音效和边框表达，但不遮挡音符。

## 5. 数据结构

派对对局上下文：

```gdscript
{
  "ruleset_id": "party_relay_v1",
  "seed": 12345,
  "players": 2,
  "team_hp": 100,
  "active_player": 1,
  "phase": 0,
  "rule_state": {},
  "modifiers": ["party"]
}
```

统计写入独立 `party_stats_v1.json`，只保存：

- 各规则游玩次数。
- 胜负和团队通关次数。
- 最佳团队分数。
- 最高救援次数。
- 炸弹胜场。

派对结果不得覆盖普通模式个人最佳鬼影或正式排行榜记录。

## 6. 技术架构

### 新增建议

- `core/rules/rule_modifier.gd`。
- `core/rules/rule_runtime.gd`。
- `core/rules/party_relay.gd`。
- `core/rules/party_coop_hp.gd`。
- `core/rules/party_bomb.gd`。
- `scenes/party_result/`。
- `ui/party_hud.gd`。
- `autoload/party_stats_store.gd`。
- 对应规则单元测试和场景测试。

### 修改点

- `mode_select.gd`：开放入口和条件检查。
- `submode_select.gd`：加载派对规则列表。
- `song_select.gd`：按规则过滤兼容歌曲。
- `gameplay.gd`：接入 RuleRuntime 和双玩家状态。
- `note_field.gd`：显示当前玩家、保护窗口和必要的轨道状态。
- `settlement.gd`：派对结果走独立结果页或明确分支。

## 7. 可访问性与体验

- 随机事件必须提前至少 2 秒预告。
- 提供“低闪烁派对特效”选项。
- 颜色状态同时用图标/文字表达，避免只靠颜色区分。
- 交接音效和炸弹提示音应与判定音效频段错开。
- 允许关闭镜头震动和强闪。

## 8. 非目标

- 首版不做联网派对。
- 首版不做十几种随机事件。
- 不允许规则突然改变而无预告。
- 不让派对成绩进入正式竞速/花式纪录。
- 不为了派对模式重写整个判定器。

## 9. 验收标准

- 只有 2P 输入可用时才开放派对入口。
- 三种首发规则都能完整进入、游玩、结算和返回。
- 交接边界音符归属稳定且可测试。
- 合作血条不会因两套 HPSystem 重复结算。
- 炸弹规则在低密度、高密度、长 Hold 谱面下都可推进。
- 任一规则脚本异常时安全结束或回退普通结果，不把玩家卡死。
- 派对成绩不更新正式个人最佳鬼影和 WEF 资格成绩。
- 性能模式下仍能清楚识别派对状态。

## 10. 风险与回滚

| 风险 | 影响 | 应对 |
|---|---|---|
| Gameplay 分支爆炸 | 维护困难 | RuleRuntime 隔离规则，不在主循环硬编码 |
| 2P 状态当前不够独立 | 统计混乱 | 先补 PlayerRunState，再开放派对 |
| 随机事件不公平 | 玩家反感 | 稳定种子、预告、密度自适应 |
| 特效遮挡音符 | 可玩性下降 | HUD 边缘表达、低闪烁模式 |
| 规则结果污染正式记录 | 竞技失真 | RunEligibility 明确拒绝 party modifier |

回滚时重新锁定派对入口；规则脚本和统计文件可以保留，不影响花式、竞速和 DIY。
