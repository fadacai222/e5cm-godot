# 总体实施方案

## 1. 总目标

在不破坏现有花式、竞速、DIY、3+1 把结算、外置曲库和原版 UI 复刻成果的前提下，建立四个长期能力：

1. **技术成长**：训练室、偏移分析、失误复盘、个人最佳鬼影。
2. **重复游玩**：每日/周常挑战、智能歌单、三首挑战路线。
3. **本地社交**：派对模式、共享血条、接力与合作规则。
4. **长期身份**：称号、头像框、玩家卡片、离线赛季与未来 WEF 联赛。

## 2. 当前项目可复用基础

- `autoload/profile_store.gd`：已有个人档案、三类等级、歌曲最高分、游玩次数、收藏夹持久化。
- `autoload/song_library.gd`：已有静态索引、外置曲库扫描、增量缓存、搜索索引和异步进度。
- `core/judge_system.gd`：已有每个判定的类型、轨道、毫秒差、分数和 Combo 变化。
- `core/score_system.gd`：已有判定计数、当前分数、最大 Combo、准确率。
- `core/match_flow.gd`：已有 3+1 把流程和经验缓存，可扩展为路线状态机。
- `scenes/gameplay/gameplay.gd`：已有完整游戏载荷、结算载荷、暂停、自动播放和演出层。
- `scenes/settlement/settlement.gd`：已有记录更新、经验结算、升级动画和继续挑战流程。
- `scenes/song_select/song_select.gd`：已有筛选、收藏、搜索、详情页和玩家信息入口。
- `ui/esc_menu.gd`、`ui/ui_kit.gd`：已有统一设置与原版街机 UI 基础。

## 3. 共享架构决策

### 3.1 离线优先

所有新功能必须在无网络时完整可用。WEF 在线能力只作为后续适配层，不得让本地挑战、奖励或历史记录依赖服务器成功响应。

### 3.2 新存档拆分

不要继续把所有内容塞进 `profile.json`。建议新增：

```text
user://feature_data/
  analytics_v1.json
  challenge_state_v1.json
  challenge_history_v1.json
  ghost_index_v1.json
  playlists_v1.json
  rewards_v1.json
  tower_runs_v1.json
  party_stats_v1.json
  season_state_v1.json
```

大型逐音符数据不得直接写 JSON 主档案，鬼影与回放使用独立压缩文件：

```text
user://ghosts/<chart_hash>/<record_id>.ghost
```

### 3.3 统一谱面身份

所有跨局、挑战、鬼影、联赛和曲包诊断都必须使用统一 `ChartIdentity`：

```gdscript
{
  "chart_hash": "谱面规范化内容哈希",
  "audio_hash": "可选，音频快速哈希",
  "sm_key": "当前相对路径，仅用于显示和迁移",
  "mode": "花式/竞速/DIY",
  "submode": "子模式",
  "difficulty": 12,
  "parser_version": 1,
  "judge_version": 1
}
```

路径不能作为唯一身份，因为用户可能移动或重命名曲包。

### 3.4 统一对局结果

建议把当前结算载荷扩展成版本化 `RunResult`，由 Gameplay 生成，Settlement、挑战、统计、鬼影和赛季共同消费：

```gdscript
{
  "schema_version": 1,
  "run_id": "UUID",
  "started_at": 0,
  "finished_at": 0,
  "chart": ChartIdentity,
  "ruleset_id": "standard",
  "player_count": 1,
  "score": 0,
  "accuracy": 0.0,
  "max_combo": 0,
  "counts": {"perfect": 0, "cool": 0, "good": 0, "miss": 0},
  "failed": false,
  "autoplay": false,
  "speed": 1.0,
  "chart_offset_ms": 0,
  "recording_id": "",
  "modifiers": []
}
```

自动播放、训练减速、调试模式和未来不被认可的修饰器必须显式标注，避免进入正式挑战和联赛成绩。

### 3.5 统一事件总线

建议新增 `autoload/feature_event_bus.gd`，仅广播领域事件，不保存业务状态：

- `run_started(context)`
- `judgement_recorded(event)`
- `combo_changed(value)`
- `run_finished(result)`
- `challenge_progressed(id, progress)`
- `reward_unlocked(id)`

这样可以让统计、挑战和鬼影监听同一份事件，避免在 `gameplay.gd` 中反复硬编码调用多个系统。

### 3.6 统一资格判定

新增 `core/run_eligibility.gd`，集中判断某次成绩是否可用于：

- 个人纪录
- 每日挑战
- 鬼影最佳记录
- 本地赛季
- 在线 WEF 提交

必须排除或降级处理：

- 自动播放
- 调试跳转
- 未完成歌曲
- 训练模式减速
- 谱面哈希不一致
- 判定器版本不兼容
- 修改后无法证明一致性的规则集

## 4. 共享服务建议

| 服务 | 职责 | 建议路径 |
|---|---|---|
| FeatureDataStore | 版本化 JSON 原子保存、备份、损坏恢复 | `autoload/feature_data_store.gd` |
| RunHistoryStore | 保存轻量对局历史与查询索引 | `autoload/run_history_store.gd` |
| ChartIdentity | 生成谱面身份和哈希 | `core/chart_identity.gd` |
| RunEligibility | 统一成绩资格规则 | `core/run_eligibility.gd` |
| FeatureEventBus | 领域事件广播 | `autoload/feature_event_bus.gd` |
| RewardCatalog | 奖励定义、解锁条件和资源映射 | `core/reward_catalog.gd` |
| RuleModifier | 爬塔、派对、挑战共用规则修饰器 | `core/rule_modifier.gd` |

## 5. 数据安全策略

- 保存必须采用“临时文件写完后替换正式文件”，避免断电产生半截 JSON。
- 每个新数据文件保留一个 `.bak`。
- 每种数据带 `schema_version`，迁移失败时只重置该功能，不重置主档案。
- 鬼影文件写入前先校验事件数量、时间单调性和谱面哈希。
- 用户导入 ZIP、挑战包、成绩包时必须防路径穿越、超大解压和恶意文件名。
- 任何在线下载内容先进入隔离目录，通过校验后再移动到正式目录。

## 6. 性能预算

### 启动

- 新功能初始化总增量目标：冷启动不超过 150ms。
- 不在启动时遍历完整曲库、鬼影目录或所有历史记录。
- 使用索引文件和按需加载。

### 游戏中

- 判定事件采集每帧不得分配大量 Dictionary；优先使用轻量对象或紧凑数组。
- 鬼影录制不得同步频繁写磁盘，应在内存中缓冲，结算时一次写入。
- 挑战系统只处理与当前规则有关的聚合事件，不扫描历史。

### 选歌

- 智能歌单查询目标：常用筛选 50ms 内返回。
- 曲包诊断必须异步分帧，并显示真实进度和取消入口。

## 7. 总体里程碑

### M0：共享基础

- 版本化存档、谱面身份、统一对局结果、资格判定、事件总线。
- 不改变玩家可见行为。

### M1：长期循环 MVP

- 智能歌单。
- 每日/周常挑战。
- 奖励与玩家卡片。

完成后，玩家每天进入游戏已经有明确目标和反馈。

### M2：技术成长 MVP

- 详细判定分析。
- 时间段循环训练。
- 个人最佳鬼影与分差显示。

### M3：玩法扩展

- 三首路线与规则修饰器。
- 派对模式首批三个规则。

### M4：内容生态

- DIY 曲包管理中心。
- 挑战记录包导入导出。

### M5：WEF

- 本地离线赛季。
- 只读在线排行榜试验。
- 有服务端验证后再开放成绩提交。

## 8. 全局验收标准

- 旧版存档、外置歌曲目录和当前发行版流程不需要用户手工迁移。
- 任一新功能数据损坏不会阻止主菜单和游戏启动。
- 所有成绩相关系统使用同一资格判定，不出现“挑战算了但联赛不算”的隐式差异。
- 训练、鬼影、派对、爬塔的规则在结算页可明确识别。
- 自动播放成绩不进入正式纪录、挑战、赛季和排行榜。
- 完整 Godot 测试集、发行内容测试和 Windows 导出烟雾测试通过。

## 9. 回滚原则

- 每个专题由独立 Feature Flag 控制。
- 新增数据文件与现有 `profile.json` 解耦。
- UI 入口可隐藏，但已产生的数据保留。
- 发现性能或兼容问题时，优先关闭功能入口，不删除玩家记录。
- 任何在线功能失败时自动回退到离线状态，不影响本地游戏。
