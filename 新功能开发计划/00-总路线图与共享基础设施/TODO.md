## Phase 1：共享数据基础

### Task 1：实现 FeatureDataStore

**目标**：提供版本化、原子写入、备份和损坏恢复。

- [ ] 新增 `autoload/feature_data_store.gd`。
- [ ] 支持 `load_json(name, version, default)`。
- [ ] 支持临时文件写入后替换正式文件。
- [ ] 保留最近一次有效 `.bak`。
- [ ] 损坏时回退备份，备份也损坏时使用默认值。
- [ ] 为迁移失败提供清晰警告日志。

**验收**：模拟半截 JSON、错误版本和备份恢复，主流程仍可启动。

### Task 2：实现 ChartIdentity

- [ ] 新增 `core/chart_identity.gd`。
- [ ] 规范化 SM、SSC、JSON 谱面用于哈希。
- [ ] 排除不影响玩法的空白和显示性元数据。
- [ ] 保留 parser/judge 版本字段。
- [ ] 为同内容不同路径生成相同 chart_hash。
- [ ] 为内容变化生成不同 chart_hash。

**验收**：重命名曲包不改变身份；修改音符或变速必须改变身份。

### Task 3：定义 RunResult

- [ ] 建立版本化结果结构和验证函数。
- [ ] 从 `gameplay.gd` 当前结算载荷无损生成 RunResult。
- [ ] 保持 Settlement 旧字段兼容层。
- [ ] 标记 autoplay、训练速度、规则修饰器和失败状态。
- [ ] 增加 run_id、开始/结束时间和 chart identity。

**验收**：当前所有结算测试继续通过，新结果可被序列化和恢复。

### Checkpoint A

- [ ] 核心测试通过。
- [ ] 旧存档和现有记录无变化。
- [ ] 未增加玩家可见入口。
