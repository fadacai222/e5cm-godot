# 09 奖励与玩家表达系统实现方案

## 0. 当前实现状态

**09.1 已于 2026-07-20 完成。** 当前版本已经从“只有库存和装备数据”升级为完整的视觉闭环：

- `RewardCatalog` 已升级到 v2，统一正式槽位、视觉参数、使用场景、回退与校验规则。
- `RewardService` 已升级到 v2，支持 v1 无损迁移、孤儿奖励保留、未读状态、严格槽位和损坏隔离。
- 已建立 `RewardAppearanceResolver`、程序化称号标签、程序化头像框和统一 `PlayerIdentityView`。
- 首批 6 个挑战奖励已经在选歌、Gameplay、ESC、个人中心和结算真实生效。
- 已建立完整奖励中心，支持全部/已拥有/未解锁、类型筛选、分页、预览、装备、取消与恢复默认。
- 已建立 `RewardPresenter`，多个奖励会在安全场景合并展示，不覆盖全连、全 P 和升级主演出。
- 已建立 `RewardMilestoneService`，接入连续活跃、首次全连/全 P、三模式等级和问题区间训练。
- 自动播放、失败成绩、普通训练不会误发正式奖励。
- 发行探针已经覆盖 RewardCatalog、统一身份组件、奖励中心和两个奖励 Autoload。

当前文档后续章节保留 09.1 的设计依据与技术契约。结算签名、音效、Combo 主题和动态头像框继续归入 09.2，不计入本轮完成范围。

---

## 1. 功能定位

奖励与玩家表达系统用于把挑战、等级、全连、训练、爬塔、派对和 WEF 的奖励，转换成玩家在多个场景中可见的身份外观。

核心原则：

1. 奖励只影响身份表达和轻量外观，不影响判定、分数、血量或成绩资格。
2. 装备一次后，选歌、Gameplay、ESC、个人中心和结算必须使用同一套结果。
3. 所有场景只读取统一的“当前装配结果”，不直接解释奖励 ID。
4. 头像必须保持原色，头像框只能叠加在外围，不能再次乘色。
5. 缺少资源、旧存档或性能模式下都必须安全回退到当前稳定版默认外观。

## 2. 09.1 首版范围

### 2.1 必须完成

首版只集中完成当前已有的三类奖励：

- 称号 `title`
- 头像框 `avatar_frame`
- 玩家卡主题 `profile_card`

并让它们在以下位置真实生效：

1. 选歌场景右上玩家信息。
2. Gameplay 顶部头像和昵称区域。
3. ESC → 用户信息。
4. 个人中心玩家卡和奖励预览。
5. 结算页玩家签名区的基础身份信息。

### 2.2 暂缓到 09.2

以下类型先保留接口，不在第一轮一起实现：

- 结算签名图片。
- 投币和菜单音效。
- Combo 数字主题。
- 动态粒子头像框。
- 商店、金币、抽奖和重复奖励兑换。

原因：当前最紧迫的问题是已经装备的奖励看不见。先把三类身份奖励完全打通，再扩声音和演出，维护成本更低。

## 3. 首批 6 个奖励的具体视觉定义

### 3.1 称号

#### `title_daily_rookie` — 今日新星

- 稀有度：普通。
- 主色：青色。
- 样式：小型切角标签。
- 适合显示在昵称下方或昵称右侧。

#### `title_rhythm_worker` — 节奏打卡员

- 稀有度：稀有。
- 主色：洋红。
- 样式：带细扫描线的双边框标签。

#### `title_weekly_runner` — 周常冲刺者

- 稀有度：稀有或史诗。
- 主色：金色。
- 样式：金色文字、青色辅助线，不使用高成本粒子。

称号显示约束：

- 中文建议最多 10 个字。
- 英文建议最多 24 个字符。
- 超长时省略，不滚动，不遮挡昵称。
- 空称号时不显示占位框。
- 称号颜色由目录定义，不允许业务场景自行判断稀有度。

### 3.2 头像框

#### `frame_neon_cyan` — 霓虹青头像框

- 青色主轮廓。
- 洋红右上和左下角标。
- 保持现有原版街机切角语言。
- 静态素材即可。

#### `frame_neon_magenta` — 霓虹粉头像框

- 洋红主轮廓。
- 青色辅助定位线。
- 可有非常轻的透明度呼吸，但性能模式必须禁用。

头像框约束：

- 透明背景。
- 不覆盖头像中央安全区。
- 头像本体始终 `modulate = Color.WHITE`、`self_modulate = Color.WHITE`。
- 紧凑玩家卡、Gameplay HUD、个人中心可以使用不同尺寸，但必须来自同一奖励定义。
- 资源缺失时回退当前稳定版默认头像环。

### 3.3 玩家卡主题

#### `card_grid_blue` — 蓝色网格玩家卡

不建议第一版制作一张固定大背景图，而是使用数据驱动的主题参数：

- 深蓝底色。
- 青色主边框。
- 洋红辅助线。
- 低透明度网格或扫描线。
- 金色段位强调色。

这样可以复用现有 `E5HudFrame`，减少不同分辨率下的拉伸和糊边问题。

玩家卡主题只允许覆盖：

- 背景填充色。
- 主边框、辅助边框和扫描线颜色。
- 标题条颜色。
- 角标样式。

不得覆盖或隐藏：

- 昵称。
- 头像。
- 称号。
- 等级。
- 段位。
- 花式、竞速、DIY 进度。

### 4.1 目录校验

启动或发行测试必须验证：

- `reward_id` 唯一。

- 所需字段齐全。
- 颜色可解析。

- `fallback_id` 存在且不会循环引用。
- 文案长度符合限制。
- 所有可装备奖励至少声明一个使用场景。

## 5. 存档升级与兼容

当前存档使用：

```gdscript
"equipped": {
  "title": "",
  "frame": "",
  "card": ""
}
```

建议升级为：

```gdscript
"equipped": {
  "title": "",
  "avatar_frame": "",
  "profile_card": "",
  "settlement_signature": "",
  "coin_sfx": "",
  "menu_sfx": "",
  "combo_theme": ""
}
```

迁移规则：

- `frame` 自动迁移到 `avatar_frame`。
- `card` 自动迁移到 `profile_card`。
- 旧键暂时保留一版只读兼容，再在下一 schema 删除。
- 未识别奖励 ID 不删除 owned 记录，只标记为 orphaned。
- 装备了缺失奖励时自动显示默认外观，但保留原 ID，资源恢复后可重新生效。

`owned` 条目建议补齐：

```gdscript
{
  "source": "daily_2026-07-20_xxx",
  "source_instance_id": "daily_2026-07-20_1",
  "unlocked_unix": 0,
  "seen": false
}
```

奖励解锁幂等键应为：

```text
reward_id + source_instance_id
```

这样未来赛季重复发同名奖励也可以被正确识别和审计。

## 6. 统一展示架构

### 6.1 RewardAppearanceResolver

新增纯逻辑解析器：

```text
ui/reward_appearance_resolver.gd
```

职责：

- 读取 RewardService 当前装备。
- 从 RewardCatalog 获取视觉定义。
- 处理旧槽位迁移。
- 处理资源缺失回退。
- 处理性能模式静态降级。
- 输出统一的 `PlayerAppearance`。

示例输出：

```gdscript
{
  "title": {...},
  "avatar_frame": {...},
  "profile_card": {...},
  "settlement_signature": {...},
  "is_default": false
}
```

场景不得直接写：

```gdscript
if reward_id == "frame_neon_cyan":
```

所有场景只能消费解析后的外观。

### 6.2 PlayerIdentityView

新增统一玩家身份组件：

```text
ui/player_identity_view.gd
```

支持三种布局预设：

- `compact`：选歌右上玩家信息。
- `gameplay`：游戏顶部头像和昵称。
- `full`：ESC 用户信息和个人中心。

组件统一管理：

- 头像。
- 头像框。
- 昵称。
- 称号。
- 等级。
- 段位。
- 玩家卡主题。
- 可选进度和状态灯。

组件监听：

- `ProfileStore.profile_changed`
- `ProfileStore.progress_changed`
- `RewardService.inventory_changed`
- `RewardService.equipped_changed`

装备奖励后不需要重进场景，下一帧立即刷新。

### 6.3 分阶段接入策略

不建议一次性删除所有现有 HUD 节点。首轮采用“适配现有节点”的方式：

1. 先让 Resolver 生成统一外观。
2. 现有选歌玩家卡调用外观应用函数。
3. 现有 Gameplay 头像 HUD 调用同一外观应用函数。
4. ESC 和个人中心再逐步替换为完整 `PlayerIdentityView`。

这样可以降低重构对当前大量未提交 UI 修改的影响。

## 7. 各场景具体展示方案

## 7.1 选歌右上玩家信息

当前玩家信息卡尺寸约为 `382 × 112`，建议扩展为不超过 `382 × 128`，仍保持在 150 像素顶栏内。

展示层级：

1. 玩家卡主题作为最底层。
2. 头像原图。
3. 装备的头像框。
4. 昵称。
5. 称号小标签。
6. 等级和段位。
7. 原有状态灯。

建议布局：

- 昵称：第一行。
- 称号：昵称下方 18～22 像素高的小标签。
- 等级和段位：第三行。
- 状态灯放底部。

约束：

- 头像框不得超过头像区域 8～12 像素。
- 称号不得挤压段位文本。
- 玩家卡主题不得与左侧训练/挑战快捷入口重叠。

## 7.2 Gameplay 顶部 HUD

当前 Gameplay 已有固定头像底板和动画框。首版不应直接替换所有现有动画资源，而应分层：

```text
默认头像底板
→ 玩家头像
→ 奖励头像框
→ 原有 VIP / 状态特效
```

称号显示在昵称附近，建议：

- 字号 16～20。
- 单行。
- 距主判定区足够远。
- 高 Combo 特效期间不增亮、不放大。

头像框和玩家卡主题只影响玩家身份区，绝不影响：

- 血条。
- 判定区。
- 音符。
- Combo 里程碑。
- AUTO 标记。

## 7.3 ESC → 用户信息

当前页面已有奖励装备卡，但只是文字列表。建议升级为：

左侧：

- 头像和实时头像框预览。
- 昵称。
- 当前称号。
- 保存昵称和更换头像。

右侧上半区：

- 当前段位和三类经验。

右侧下半区：

- 三个装备槽预览：称号、头像框、玩家卡。
- 已拥有奖励列表。
- 装备、取消装备、恢复默认。
- 稀有度和获取来源。

点击奖励时必须先实时预览，再确认装备；踏板确认可直接装备。

## 7.4 个人中心

个人中心保留现有“我的奖励”入口，但改为完整预览：

- 左侧显示当前完整玩家卡。
- 右侧按类别展示库存。
- 支持已拥有/未解锁筛选。
- 未解锁奖励显示获取条件。
- 当前装备项有明确标记。
- 新奖励显示红点，查看后标记 `seen = true`。

## 7.5 结算页

09.1 只显示基础身份：

- 玩家昵称。
- 当前称号。
- 小型头像框缩略预览。

完整“结算签名奖励”留到 09.2，避免和现有升级、全连、全 P 动画争夺空间。

### 8.1 头像框尺寸

每个头像框至少提供：

- compact：适配选歌小头像。
- gameplay：适配 Gameplay 头像区。
- large：适配 ESC 和个人中心。

或使用一张高分辨率透明素材并通过安全区规范缩放。

### 8.2 性能要求

- 静态头像框只增加 1 个 TextureRect。
- 动态头像框最多 1 个 ShaderMaterial，不允许每帧生成节点。
- 玩家卡主题优先复用 `E5HudFrame` 参数，不额外铺大型半透明视频。
- 性能模式禁用呼吸、流光、粒子，只保留静态颜色和边框。
- 选歌页所有身份外观总额外绘制节点建议不超过 12 个。

## 9. RewardService v2

在现有服务基础上增加：

- `unlock(reward_id, source_instance_id, source)`。
- `mark_seen(reward_id)`。
- `unseen_count()`。
- `equip(slot, reward_id)` 的严格槽位校验。
- `reset_slot(slot)`。
- `current_loadout()`。
- `validate_and_repair()`。
- 存档 schema 迁移。
- 备份恢复和损坏隔离。

新增信号：

```gdscript
signal reward_unlocked(reward_id: String)
signal reward_seen(reward_id: String)
signal loadout_changed(loadout: Dictionary)
```

`equipped_changed` 可保留兼容，但新 UI 优先监听 `loadout_changed`。

## 11. 公平与可访问性边界

绝对禁止奖励改变：

- 判定窗口。
- 谱面偏移。
- 音符透明度。
- 血量。
- Combo 计算。
- 得分倍率。
- 成绩资格。
- WEF 尝试次数。

视觉要求：

- 称号与边框不能快速闪烁。
- 色彩之外还要有文字或结构差异，不能只靠颜色表达稀有度。
- 动效必须可在性能模式或外观设置中关闭。
- 头像框不能降低头像识别度。

## 12. 测试方案

### 12.1 目录与存档

- RewardCatalog v2 schema 校验。
- 重复 ID 检测。
- 缺资源回退。
- v1 `frame/card` 到 v2 槽位迁移。
- 损坏存档恢复。
- 重复解锁幂等。
- seen/unseen 状态。

### 12.2 展示一致性

同一套装备必须在以下位置显示一致：

- 选歌玩家信息。
- Gameplay HUD。
- ESC 用户信息。
- 个人中心。
- 结算身份区。

### 12.3 头像原色

自动化验证所有场景中的头像节点：

```gdscript
modulate == Color.WHITE
self_modulate == Color.WHITE
```

并确保奖励头像框位于头像外层，而不是改变头像材质颜色。

### 12.4 实时刷新

- 场景保持打开时装备奖励。
- 下一帧所有可见身份组件刷新。
- 不需要重新进入场景。
- 取消装备立即恢复默认。

### 12.5 性能与发行

- 选歌页身份区 1000 次刷新不泄漏节点。
- 性能模式只加载静态资源。
- 发行资产探针覆盖所有奖励资源。
- EXE/PCK 和安装包烟雾测试通过。

## 15. 风险与回滚

| 风险 | 处理 |
|---|---|
| 多个场景分别实现导致效果不一致 | 使用 RewardAppearanceResolver 和 PlayerIdentityView |
| 当前 HUD 已有复杂动画，直接替换容易回归 | 首轮适配现有节点，分阶段替换 |
| 头像框再次导致头像发暗 | 头像和边框分节点，头像强制保持白色调制 |
| 玩家卡主题降低文字可读性 | 目录校验最小对比度，核心文字保留固定描边 |
| 资源缺失导致存档无法加载 | fallback_id 和默认外观 |
| 动态奖励掉帧 | 性能模式静态回退，首版以静态为主 |
| 旧槽位名称与新槽位冲突 | v1→v2 明确迁移并保留一版兼容 |
| 工作区现有 UI 改动较多 | 小步接入、目标场景回归、不大规模重写场景树 |

回滚时：

- RewardService 保留 owned 和 equipped 数据。
- Resolver 强制返回默认外观。
- 隐藏奖励预览和装配入口。
- 不删除玩家已获得的奖励，后续修复后可重新显示。
