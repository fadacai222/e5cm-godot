# 每日周常挑战实现方案

> 实施状态（2026-07-20）：02 专题已完成并进入发行包。每日 3 项、周常 5 项、稳定生成、资格隔离、时钟保护、结算推进、表达奖励、异常恢复和 Windows 安装验证均已落地。

## 0. 最终实现摘要

- 入口：大模式选择页“今日挑战”，支持鼠标、`C` 键以及左右踏板 + 确认踏板组合。
- 任务：20 个模板；每日 3 项，周常 5 项；每日固定“普通 + 进阶 + 自适应”难度骨架。
- 资格：只接受正式非自动播放结果；训练、自动播放和调试结果明确拒绝。
- 进度：Settlement 提交统一结果，使用 `run_id` 幂等处理。
- 奖励：称号、头像框、玩家卡；完成即自动入库，可在个人中心查看和装备。
- 存档：挑战与奖励分离，均采用临时文件和备份恢复。
- 性能：首次全曲库能力判断由 6223ms 优化到约 508ms，同周期后续进入不再扫描。
- 随机选歌模板已经实现，但在 06 的随机入口接入前不会进入候选池，避免死任务。

## 1. 功能定位

挑战系统解决“玩家进入游戏后不知道玩什么”的问题。它必须建立在现有曲库、歌曲记录、模式等级和结算数据之上，不引入强制联网、不制造无法完成的随机任务，也不把玩家逼去玩不存在或损坏的谱面。

核心目标：

- 每日提供 3 个短目标，单次游玩 10～30 分钟可完成大部分。
- 每周提供 3～5 个长期目标，鼓励跨模式游玩。
- 奖励只提供表达和收藏价值，不影响判定强度或竞技公平。
- 同一自然日内任务稳定，不因重启或时区漂移反复刷新。

## 2. 玩家流程

### 主入口

当前实现把“今日挑战”入口放在大模式选择页，个人中心提供独立的“我的奖励”库存与装备页：

- 今日挑战完成度 `1 / 3`。
- 本周挑战完成度 `2 / 5`。
- 连续活跃天数。
- 即将获得的奖励预览。

### 结算反馈

结算页在经验动画之后显示短提示：

```text
每日挑战推进：竞速模式完成 10 星歌曲 1 / 1
奖励已解锁：霓虹青头像框
```

提示不得抢占 ALL COMBO / ALL PERFECT 动画，也不能延长所有玩家的结算时间。无进度时不显示。

## 3. 挑战模板

建议先实现纯结果型模板，避免监听复杂实时行为。

### 单局模板

- 指定大模式完成一首。
- 指定星级以上通关。
- 获得 A / S 级以上。
- 达到指定 Combo。
- Miss 不超过 N。
- Good 不超过 N。
- 准确率达到 X%。
- 使用随机歌曲完成一局。
- 完成一首从未玩过的歌曲。
- 打破一首个人纪录。
- 使用反向、隐藏或指定皮肤完成一局。

### 累计模板

- 累计完成 N 首。
- 累计获得 N 个 S。
- 花式、竞速、DIY 各完成 N 首。
- 累计达成 N 次 Perfect。
- 累计游玩 N 分钟。
- 完成 N 首不同歌曲。

### 2P 模板

- 2P 完成一局。
- 情侣模式通关。
- 双方均达到 A 级。

2P 任务必须只在检测到可用 2P 输入或玩家主动启用 2P 后进入候选池，避免单人玩家永远无法完成。

## 4. 生成规则

### 4.1 稳定种子

每日任务种子：

```text
hash(日期 + 本地档案ID + challenge_catalog_version)
```

周常任务种子：

```text
hash(ISO周编号 + 本地档案ID + challenge_catalog_version)
```

同一天重启不变化；升级模板版本后可有意刷新。

### 4.2 时区

使用用户本地日期，但保存：

- `generated_for_date`
- `last_seen_unix`
- `timezone_offset_minutes`

检测系统时钟大幅倒退时，不立即重复发奖励；保持当前任务直到真实时间追上或玩家手工重置。不能因为改系统时间无限刷奖励。

### 4.3 可完成性过滤

生成任务前查询 SongLibrary 和玩家状态：

- 目标模式必须至少有一首可玩歌曲。
- 星级阈值必须存在满足条件的谱面。
- “从未玩过”必须确实存在未游玩歌曲。
- “打破纪录”应选择有历史记录但仍有改进空间的歌曲，不指定已全 P 的谱面。
- DIY 任务只有 DIY 曲库可用时才生成。
- 2P 任务默认不进入单人任务池。

无法满足时替换模板，而不是降低到永远显示 0/1。

## 6. 技术架构

### 实际新增

- `core/challenge_catalog.gd`：20 个模板、描述、资格和进度计算。
- `core/challenge_generator.gd`：稳定生成、类型分散和难度分层。
- `core/reward_catalog.gd`：表达奖励目录。
- `autoload/challenge_service.gd`：周期、进度、幂等、时钟保护和补发。
- `autoload/reward_service.gd`：独立奖励库存与装备。
- `ui/challenge_panel.gd`：模式页全屏挑战中心。
- `ui/challenge_progress_popup.gd`：结算非阻塞推进提示。
- `tests/test_challenge_system_20260720.gd`：生成、资格和幂等。
- `tests/test_challenge_lifecycle_20260720.gd`：60 天、时区、坏存档、恢复和奖励。
- `tests/test_challenge_ui_integration_20260720.gd`：入口、个人中心、结算闭环。
- `tests/test_challenge_capability_performance_20260720.gd`：全曲库能力扫描性能。

### 实际接入点

- `gameplay.gd`：生成唯一 `run_id`，携带正式成绩资格及当前设置状态。
- `settlement.gd`：在正式记录落盘后向 `ChallengeService` 提交结果并显示推进摘要。
- `SongLibrary.challenge_capabilities_snapshot()`：直接读取轻量索引摘要，不触发完整目录扫描。
- `RewardCatalog` / `RewardService`：完成后自动解锁并独立持久化。
- `mode_select.gd`：挑战中心入口。
- `profile.gd`：奖励库存与装备入口。

当前没有强行引入尚未落地的全局 `FeatureEventBus`；02 使用明确的 Settlement 结果适配器，后续共享事件总线完成后可迁移而不改变挑战数据契约。

## 7. 奖励与领取

MVP 建议完成即自动领取，避免玩家忘记点领取。奖励类型：

- 称号。
- 头像框。
- 玩家卡片背景。
- Combo 数字装饰。
- 结算签名。
- 投币音效或 UI 音效。

不提供经验倍率、判定加宽或血量加成，避免破坏竞技公平。

## 8. 难度分层

根据玩家最高模式等级和最近 20 局表现，把任务分为：

- 普通：完成即可。
- 进阶：A 级、100 Combo、较高星级。
- 挑战：S 级、低 Miss、高准确率。

每日组合建议：1 普通 + 1 进阶 + 1 自适应。周常可有一个困难目标，但不能要求全 P 这种极端条件作为唯一周常。

## 9. 非目标

- MVP 不需要服务器下发任务。
- 不做付费刷新。
- 不允许无限手动刷新刷奖励。
- 不生成当前曲库无法完成的任务。
- 自动播放、训练模式和调试成绩不推进正式挑战。

## 10. 验收标准

- 同一玩家同一天重启任务完全一致。
- 次日只刷新每日，跨周才刷新周常。
- 系统时间倒退不会重复奖励。
- 空 DIY、无 2P、低星曲库均不会生成不可完成任务。
- 结算推进与 RunResult 一致，不重复计算。
- 同一个 run_id 处理两次不会重复推进。
- 自动播放和训练结果不推进挑战。
- 奖励解锁失败时，挑战保持已完成并可补发。

## 11. 风险与回滚

| 风险 | 影响 | 应对 |
|---|---|---|
| 随机任务不可完成 | 玩家挫败 | 生成前做曲库和档案能力过滤 |
| 改系统时间刷奖励 | 奖励失去意义 | 时钟倒退保护、已领取 ID 幂等 |
| 结算重复触发 | 重复进度和奖励 | 以 run_id 做幂等处理 |
| 模板版本变化破坏旧任务 | 任务无法解析 | 实例保存完整参数和 eligibility_version |
| 任务过多变成打工 | 降低乐趣 | 每日只 3 个，奖励偏表达，不制造惩罚 |

回滚时隐藏挑战入口并停止生成新任务；已解锁奖励继续有效。
