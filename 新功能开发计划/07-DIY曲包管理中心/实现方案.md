# DIY 曲包管理中心实现方案

## 1. 功能定位

DIY 曲包管理中心负责“导入、诊断、隔离、修复提示和重建索引”，不是谱面编辑器。它要解决用户把 SM、SSC、JSON 和相关音频资源放入外置 `songs/diy` 后，遇到加载慢、资源缺失、异常时长、变速花活和格式兼容问题时无从判断的痛点。

目标：

- 新增曲包有明确扫描状态。
- 损坏曲包不拖垮整个选歌场景。
- 玩家能看到系统应用了哪些兼容补丁。
- ZIP 导入安全、可取消、可回滚。
- 诊断与 SongLibrary 当前缓存机制共用事实来源，不建立第二套扫描器。

## 2. 入口与流程

### 入口

在 DIY 子模式页或选歌设置中增加“曲包管理”。

### 首页

每个曲包显示：

- 曲包名称。
- 歌曲和谱面数量。
- 最近扫描时间。
- 状态：正常 / 警告 / 错误 / 已隔离 / 待重新扫描。
- 索引命中或重新解析数量。

### 详情

按歌曲列出：

- 谱面格式与星级。
- 音频、封面、视频存在性。
- 音频时长与谱面时长。
- BPM、停止、变速、负时间音符等异常。
- 使用的兼容补丁。
- 可玩 / 降级可玩 / 不可玩。

## 3. 诊断规则

### 文件级

- 缺少谱面。
- 缺少音频。
- 音频无法解码。
- 封面或视频损坏。
- 文件名包含 Windows 非法或保留名称。
- 路径过长。
- 大小异常。
- 编码无法可靠识别。

### 谱面级

- 空谱面或无有效音符。
- 负时间音符。
- 音符时间非单调。
- Hold 结束早于开始。
- 同轨 Hold 重叠。
- 音符超出音频结尾。
- BPM 为 0、负数或极端值。
- 变速/停止数量异常。
- Fake Notes 是否被正确排除。
- JSON 字段缺失或类型异常。
- 谱面时长明显大于音频时长。

### 兼容补丁展示

复用 `SmParser` 当前补丁记录，显示类似：

```text
已应用：fake_notes_excluded_from_judgement
已应用：duration_clamped_to_audio
警告：BPM 在 01:37 跳变至 999
```

不把所有异常都自动修改原文件。默认只做运行时兼容和提示。

## 4. 扫描架构

### 单一事实来源

SongLibrary 继续负责扫描、缓存和歌曲模型。新增 `ChartDiagnostics` 只对 SongLibrary 返回的谱面和原始文件进行诊断。

建议：

- 快速检查：目录签名、文件存在性、缓存状态。
- 深度检查：解析谱面、音频时长、时间线一致性。
- 深度检查按需启动，异步分帧或后台线程执行。

### 进度

复用现有 `scan_progress`，新增诊断进度：

- 正在检查目录。
- 正在验证音频。
- 正在解析谱面。
- 正在生成报告。

所有长任务必须可取消。取消后保留已完成结果，并标记报告不完整。

## 5. 报告数据

建议独立缓存：

```text
user://cache/diy_diagnostics_v1.json
```

按目录签名和 chart_hash 保存：

```gdscript
{
  "schema_version": 1,
  "folder_signature": "...",
  "chart_hash": "...",
  "severity": "warning",
  "issues": [],
  "compat_patches": [],
  "checked_at": 0,
  "tool_version": 1
}
```

目录或文件签名未变化时直接复用。诊断缓存损坏只导致重新检查。

## 6. 隔离机制

不可玩或恶意曲包可移动到：

```text
songs/_quarantine/<timestamp>-<safe_name>/
```

要求：

- 移动前显示原因和目标路径。
- 不自动永久删除。
- 提供恢复。
- 索引中立即移除原条目。
- 移动失败时保持原状态，不写“已隔离”。

发行版安装目录可能无写权限，因此必须检测实际 songs 根目录权限，并给出明确错误。

## 7. ZIP 导入

### 流程

1. 用户选择 ZIP。
2. 先读取目录表，不直接解压。
3. 检查总文件数、总解压大小、单文件大小和路径。
4. 解压到临时隔离目录。
5. 执行快速诊断。
6. 用户确认曲包名和目标目录。
7. 原子移动到 `songs/diy/<pack>`。
8. 仅失效该曲包相关缓存并增量建索引。

### 安全限制

- 拒绝 `../`、绝对路径、盘符路径和符号链接。
- 设置压缩比、文件数和总大小上限，防 ZIP 炸弹。
- 拒绝可执行文件或默认不复制。
- 文件名规范化，避免 Windows 保留名和结尾点/空格。
- 同名目标不覆盖，提供改名或取消。

## 8. 自动修复边界

允许的一键修复：

- 重建索引。
- 清除该曲包缓存。
- 重新匹配同目录音频和封面。
- 生成缺失元数据侧车文件。
- 规范化显示名称，但不改谱面判定内容。

默认不允许：

- 擅自删除音符。
- 修改 BPM、停止和变速。
- 裁剪音频。
- 覆盖原谱面。

如未来提供修复，必须先备份原文件并生成差异报告。

## 9. 技术结构

新增建议：

- `core/chart_diagnostics.gd`
- `autoload/diy_pack_service.gd`
- `scenes/diy_manager/`
- `ui/diagnostic_issue_row.gd`
- `tools/import_diy_pack.gd` 或安全原生解压适配
- `tests/test_chart_diagnostics.gd`
- `tests/test_diy_zip_security.gd`
- `tests/test_diy_quarantine.gd`

主要接入：

- `song_library.gd` 提供按曲包失效和扫描接口。
- `sm_parser.gd` 输出结构化兼容补丁和解析警告。
- `submode_select.gd` 或 DIY 选歌页增加管理入口。

## 10. 非目标

- 不做完整谱面编辑器。
- 不默认修改用户原谱面。
- 不在游戏启动时自动深度扫描全部曲库。
- 不让单个坏曲包阻止其他曲包进入选歌。
- 不在未校验前把 ZIP 解压到正式 songs 目录。

## 11. 验收标准

- 正常曲包快速命中缓存。
- 修改一个文件只重新诊断相关曲包或谱面。
- 缺音频、坏 JSON、极端 BPM、超长时长和重叠 Hold 均能给出稳定报告。
- 单个坏曲包不拖慢全部 DIY 选歌。
- ZIP 路径穿越和超大解压被拒绝。
- 隔离、恢复和索引失效一致。
- 取消深度扫描后 UI 可继续使用。
- 无写权限时不丢文件，并显示可验证路径。

## 12. 风险与回滚

| 风险 | 处理 |
|---|---|
| 深度扫描耗时过长 | 按需启动、异步进度、缓存和取消 |
| 自动修复破坏谱面 | MVP 不改判定内容，只报告和备份 |
| ZIP 恶意路径或炸弹 | 预扫描、路径规范化、大小和数量上限 |
| 隔离移动失败 | 移动成功后才更新状态和索引 |
| 诊断规则误报 | 严重级别区分，允许忽略单项警告 |

回滚时隐藏管理入口；SongLibrary 当前扫描和缓存继续工作，诊断缓存可安全删除。
