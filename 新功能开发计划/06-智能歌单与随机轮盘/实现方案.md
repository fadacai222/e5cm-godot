# 智能歌单与随机轮盘实现方案

## 1. 功能定位

当前曲库已有一万余谱面变体、搜索索引、收藏和最高分记录，但玩家仍主要靠手工筛选。智能歌单要把曲库和历史记录组合成可直接游玩的动态列表，让大曲库不再只是“数量很多”。

这是推荐最先实施的玩家可见功能：依赖少、风险低、回报高。

## 2. 首批智能歌单

- 差一点全连：历史最好 Miss 为 1～5。
- 差一点 S：最好准确率接近 S 阈值。
- 最近没玩：按最后游玩时间排序。
- 从未玩过：没有有效记录的谱面。
- 最近新增：曲库首次发现时间较新。
- 同星级随机：以当前选择星级为范围。
- 同 BPM 区间：适合连续练习节奏。
- 热身三首：低于玩家舒适难度。
- 冲刺三首：接近个人上限。
- 花式/竞速/DIY 轮换。
- 收藏夹随机。
- 今日推荐三首：稳定种子，每天不变。

## 3. 记录补充

当前 `records.json` 主要保存最高分和游玩次数。智能歌单需要扩展轻量记录：

```gdscript
{
  "chart_hash": "...",
  "last_played_at": 0,
  "first_played_at": 0,
  "best_accuracy": 0.0,
  "best_miss": 999,
  "best_grade": "",
  "last_score": 0,
  "last_accuracy": 0.0,
  "last_miss": 0
}
```

旧记录缺字段时按默认值兼容。路径继续可用于显示，但查询应逐步迁移到 chart_hash。

## 4. 查询架构

建议新增纯查询服务 `SmartPlaylistService`：

```gdscript
query(playlist_id: String, context: Dictionary) -> Array
```

输入：

- 当前大模式、子模式。
- 当前星级和 BPM。
- 玩家等级与最近表现。
- 排除的 chart_hash。
- 最大结果数。

输出仍使用 SongLibrary 当前歌曲字典，避免新建第二套歌曲模型。

常用查询结果可缓存，以下事件失效：

- 新歌曲被扫描。
- 新对局记录写入。
- 收藏变化。
- 日期变化。

## 5. 今日推荐

使用：

```text
hash(本地日期 + 档案ID + 推荐算法版本)
```

生成固定三首：

1. 热身：低于近期舒适难度。
2. 主练：接近近期稳定难度。
3. 挑战：略高于稳定难度，但最近并非连续失败。

不能只按等级推难度，应参考最近 20 局：

- 通关率。
- 准确率。
- Miss 数。
- 最近主动选择星级。

候选不足时放宽模式或星级，并在 UI 标明推荐原因。

## 6. 随机轮盘

### 交互

在选歌页增加“随机轮盘”：

- 先选择范围：当前筛选、收藏夹、智能歌单、全曲库。
- 按确认后封面快速滚动。
- 动画结束停在预先计算的结果。
- 再次确认进入详情或直接开局。

### 公平和稳定

结果必须在动画开始前生成。不能让帧率、按钮连按或 Tween 完成时间决定最终歌曲。

建议 seed：

```text
hash(session_id + spin_count + active_filter_fingerprint)
```

支持“排除最近随机到的 5 首”，避免连续重复。

### 性能

轮盘只预加载少量显示封面，不能一次加载整个曲库图片。滚动过程复用 7～12 个卡片节点并替换纹理。

## 7. 歌单队列

增强版允许把智能歌单保存为 3～10 首播放队列：

- 当前顺序。
- 随机顺序。
- 完成后自动进入下一首详情。
- 中途退出时保留进度。

队列不是爬塔，不修改血量或规则；每首仍按普通成绩结算。

## 8. UI 位置

- 选歌底栏增加“推荐/轮盘”入口，避免再塞过多常驻按钮时可合并到歌曲分类弹层。
- 首页展示“今日三首”。
- 歌曲卡片增加简短推荐理由：`差 1 Miss 全连`、`14 天未玩`、`今日挑战曲`。
- 所有动态歌单都可一键清除并回到全部歌曲。

## 9. 技术结构

新增建议：

- `core/smart_playlist_service.gd`
- `core/recommendation_profile.gd`
- `autoload/playlist_store.gd`
- `scenes/song_select/random_wheel.gd`
- `tests/test_smart_playlists.gd`
- `tests/test_daily_recommendation.gd`
- `tests/test_random_wheel_determinism.gd`

主要修改：

- `profile_store.gd` 或 RunHistoryStore 补充轻量历史字段。
- `song_library.gd` 提供按元数据批量查询接口。
- `song_select.gd` 增加动态数据源与轮盘入口。
- `song_card_glass.gd` 显示推荐原因。

## 10. 非目标

- 不做云端推荐算法。
- 不读取玩家隐私或外部账号。
- 不一次性加载完整曲库封面。
- 不把每日推荐设计成必须完成的惩罚任务。
- 不让随机动画影响真实结果。

## 11. 验收标准

- 所有歌单只返回真实存在且可玩的谱面。
- 空结果有安全提示和放宽入口。
- 今日推荐同一天保持一致，次日刷新。
- 新增歌曲、完成对局、收藏变化后相关缓存正确失效。
- 轮盘结果与帧率、动画时长无关。
- 轮盘连续执行 100 次无节点泄漏和明显内存增长。
- 常用歌单在完整索引下目标 50ms 内返回。
- 普通搜索、筛选和收藏夹行为无回归。

## 12. 风险与回滚

| 风险 | 处理 |
|---|---|
| 旧记录字段不足 | 默认值迁移，功能降级而不报错 |
| 推荐总是同一批歌 | 多样性惩罚和最近排除列表 |
| 查询扫描全量过慢 | 预建轻量元数据索引和结果缓存 |
| 轮盘加载封面卡顿 | 小节点池复用和异步纹理加载 |
| 推荐难度不合适 | 结合最近表现并显示推荐原因 |

回滚时隐藏智能歌单和轮盘入口；现有搜索、筛选和记录结构继续工作。
