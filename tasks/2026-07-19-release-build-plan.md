# E5CM Windows 发行版构建计划（2026-07-19）

## 目标

在不移动、不裁剪、不修改开发用完整 `songs/` 曲库的前提下，生成独立的发行暂存曲库；每个可玩子模式稳定随机抽取最多 4 首可播放歌曲，导出 Windows EXE/PCK，编译 Inno Setup 安装包，完成便携版与安装版烟雾测试，并将可复现构建流程固化到项目根目录脚本。最终提交并推送除歌曲内容、暂存目录和构建产物之外的全部工作区变更。

## 核心约束

- 完整 `songs/` 只读使用，禁止移动、重命名、替换或清空。
- 打包歌曲只进入 `.release-staging/songs/` 和 `release/E5CM/songs/`。
- 每个可玩子模式最多 4 首；不足 4 首时保留全部，不复制凑数。
- 抽样必须可复现：固定种子，同一曲库得到同一结果。
- `songs/**`、`release/**`、`.release-staging/**` 不进入 Git。
- 根目录打包脚本使用 UTF-8 BOM，兼容 Windows PowerShell 5.1 的中文显示与路径。
- 构建失败时必须恢复开发用完整歌曲索引，且不得破坏完整曲库。

## 阶段与验收

### 阶段 1：环境与现状审计

- [ ] 确认 Godot 控制台、Windows 导出模板、Python、ImageMagick、Inno Setup 可用。
- [ ] 确认磁盘空间足够，完整曲库仍位于项目 `songs/`。
- [ ] 检查当前 Git 改动与忽略规则，防止歌曲和产物误提交。

### 阶段 2：无损打包流水线

- [ ] 修正发行脚本，彻底移除“归档/替换完整 songs”的破坏性逻辑。
- [ ] 发行准备阶段创建专用暂存 songs，并生成对应静态索引和清单。
- [ ] 导出完成后自动恢复完整开发索引。
- [ ] 根目录提供一键 PowerShell 脚本：预检、抽歌、导出、安装包、烟测、清理/恢复。
- [ ] 脚本支持失败退出码与明确错误信息，不静默吞错。

### 阶段 3：实际构建与验证

- [ ] Godot 项目无脚本解析错误。
- [ ] 成功生成 `release/E5CM/E5CM.exe` 与 `E5CM.pck`。
- [ ] 便携版曲库清单与实际目录一致，每个模式不超过 4 首。
- [ ] 游戏发行资产探针无头运行退出码为 0。
- [ ] 成功生成 `release/E5CM-Setup-0.9.1.exe`。
- [ ] 静默安装、启动探针、卸载、桌面快捷方式验证全部通过。
- [ ] 构建前后完整 `songs/` 路径与总体规模保持不变。

### 阶段 4：版本控制与交付

- [ ] 检查暂存差异，不包含歌曲、安装包、EXE/PCK、缓存、凭据。
- [ ] 提交当前工作区除 songs/构建产物外的全部变更。
- [ ] 推送到 `origin/main`。
- [ ] 输出构建产物路径、大小、歌曲抽样统计、提交哈希和推送结果。

## 主要风险与处理

| 风险 | 处理 |
|---|---|
| 旧脚本会把完整 songs 移出项目 | 删除破坏性 finalize 行为，改为只清理暂存和恢复索引 |
| Godot 导出时把 51GB 曲库打进 PCK | export preset 强制排除 `songs/**`，歌曲仅复制到便携目录 |
| 中文 PowerShell 脚本乱码 | 文件写入 UTF-8 BOM，并在脚本开头设置 UTF-8 控制台编码 |
| 抽到缺谱面/缺音频歌曲 | 只从同时含谱面和音频的目录抽样，并验证索引引用文件存在 |
| 构建中断留下精选索引 | `try/finally` 无条件恢复完整索引 |
| Git 误提交歌曲或发行包 | `.gitignore` + 提交前 `git status`/`git diff --cached` 双重检查 |
| 安装包看似成功但不能运行 | 静默安装后运行发行资产探针，再卸载并清理临时目录 |
