# 项目找茬问题修复计划

## 目标
在不覆盖当前结算/成就动画未提交改动的前提下，修复审计中确认的项目、测试、打包和兼容性问题，并以 Godot 4.6.2 无界面回归、真实发行资源探针和静态检查作为完成标准。

## 实施原则
- 先修可导致发版失败、曲库异常或真实交互错误的问题。
- 所有行为修改先用现有失败测试复现，必要时修正错误测试夹具。
- 不删除或重写当前工作区内与成就动画相关的未提交修改。
- 打包临时数据必须位于暂存目录，开发索引不得被构建流程长期覆盖。
- 固定 1920×1080 逻辑画布保留，但窗口尺寸必须适配较小工作区和 DPI 缩放。

## 阶段 1：工程卫生和构建隔离
1. 删除根目录 Windows 保留名 `NUL` 文件并防止再次生成。
2. 恢复/重建完整开发曲库索引。
3. 重构发行构建，使精选索引只进入暂存/导出过程，中断后开发索引保持不变。
4. 修正发行内容测试，使其针对发行暂存或发行目录，而不是完整开发曲库。

## 阶段 2：选歌交互与测试可靠性
1. 修复歌曲详情/筛选遮罩的空白关闭和事件消费。
2. 修复多页翻页按钮初始化、显隐与翻页时序。
3. 修复 `test_autotest_isolation` 的场景脚本类型错误。
4. 缺失 parity 夹具时显式跳过相关测试，避免无意义红灯和 JSON 解析噪音。
5. 修正场景编辑器预览测试，使动态构建场景采用可验证的运行时契约，不强制伪造编辑器节点。

## 阶段 3：兼容性与可移植性
1. 启动时根据当前屏幕可用工作区缩放窗口，避免低分辨率和高 DPI 下超出屏幕。
2. 将默认帧率/垂直同步调整为更稳妥的默认值，同时保留 240 FPS 选项。
3. 增加兼容渲染启动验证，检查 `gl_compatibility` 路径。
4. 去除迁移/归一化工具中的本机绝对项目路径，改为脚本目录推导和可覆盖参数。

## 阶段 4：回归与发行验证
1. 运行核心逻辑、场景、选歌、曲库、DIY、异步音频和结算相关测试。
2. 运行所有可执行 Godot 测试，记录真正失败项并修复。
3. 运行 Godot 编辑器无界面解析。
4. 运行现有发行 EXE 资源探针；条件允许时重新导出便携版并验证。
5. 检查 Git diff、路径大小写、保留设备名、残留进程和构建临时目录。

## 风险
- 完整曲库索引重建需要枚举约一万首歌曲，耗时和磁盘读取量较大。
- 选歌输入测试依赖真实 Viewport 事件时序，headless 驱动可能与窗口模式存在差异，需同时验证状态契约。
- 当前工作区存在大量未提交成就动画改动，所有编辑必须避开相关文件或只做不冲突的局部修改。
